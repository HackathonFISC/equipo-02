## Completed items

1. Queue claims now enforce per-candidate session-version ordering in both the
   in-memory and SQL stores. A future-version job is released/retried until its
   earlier turn commits; it is not terminally dead-lettered as a stale job.
2. Added `apps/web/tests/chat-jobs.integration.test.ts`, an opt-in
   PostgreSQL/Neon fixture suite covering migration-backed insert, duplicate-key
   reuse, lease claim, success acknowledgement, and concurrent `SKIP LOCKED`
   claims.
3. Replaying an existing succeeded idempotency key returns HTTP 200 with the
   existing job and completed result. Queued/running/failed replays retain the
   job-handle behavior.
4. Added regression tests for future-version ordering and completed replay.
5. Worker context-loading and chat execution exceptions are now caught,
   classified safely, and routed through retry/terminal settlement so claimed
   jobs cannot be stranded in `running`; regression tests cover context and
   handler failures.
